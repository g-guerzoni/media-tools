# Pinned dependency set, so an install reproduces what CI tested.
#
# Why this file exists: media-tools pulls in Deno through yt-dlp[default,deno],
# and yt-dlp hands site-supplied JavaScript to it to solve signature challenges.
# That is safe only because of the flags yt-dlp passes -- no --allow-* permission,
# plus --no-prompt so one cannot be granted mid-run. Verified 2026-09-25: under
# those flags a script gets NotCapable for filesystem, environment and network.
#
# Unpinned, a yt-dlp release could change those flags and be installed with nobody
# looking. The pin is what makes that a deliberate act instead of a silent one.
#
# The cost, and it is real: yt-dlp breaks when sites change their challenges, so
# this file needs deliberate and fairly frequent bumps. A stale yt-dlp fails
# loudly (extraction stops) rather than dangerously, which is why the trade is
# acceptable -- but it is a trade, not a free win.
#
# CI runs the matrix against this file AND one unpinned job, so upstream breakage
# still surfaces instead of being hidden by the pin.
#
# Regenerate: .venv/bin/pip freeze --exclude-editable | sort
